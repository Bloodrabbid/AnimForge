# AnimForge

Инструмент анимации под любую игру: рецепты с параметрами + ручной слой правок + клипы, экспорт в glTF, проверка в Godot.
Одно ядро команд (`packages/core`) — его вызывают CLI, MCP и веб-интерфейс.

## Быстрый старт

```sh
pnpm install
P=projects/fish-demo
pnpm af help                                   # все команды с аргументами (JSON)
pnpm af info --project $P                      # кости, цепочки, клипы
pnpm af preset.list --project $P               # пресеты библиотеки
pnpm af recipe.set --clip swim --layer wave --params '{"period":1.6}' --project $P
pnpm af key.set --clip swim --bone spine_5 --axis lateral --t 1.0 --v 25 --project $P
pnpm af sheet --clip swim --view top --out out/swim.png --project $P   # «глаза»: лист кадров через Blender
pnpm af export --out out/fish.glb --project $P                         # glTF для Blender/Godot/любого движка (.fbx — FBX)
pnpm af verify --project $P                                            # проверка в Godot без окна
```

## make: от модели до файла одним вызовом

```sh
pnpm af make --project out/baker --file ~/models/baker.glb \
  --clips "ленивая ходьба; удар; дыхание" \
  --style '{"stylization":"cartoon","role":"npc","fps":30}' \
  --godot ~/games/clay/godot/assets/anim --send
```

Одна команда делает всё по порядку:

1. Создаёт проект: импорт модели и авториг, если скелета нет.
2. Собирает клипы из библиотеки. Если анатомических пределов ещё нет, ставит их.
3. Экспортирует glb в `out/<имя>.glb` и кладёт копию в папку игры на Godot.
4. Рендерит видео всех клипов с подписями в `out/<имя>.mp4`.
5. С `--send` присылает видео и glb в Telegram.

**Клипы** перечисляются через `;`:
- `имя=пресет{"period":0.6}` — точный пресет с параметрами;
- просто `пресет`;
- слова: «ленивая ходьба», «ходьба как у голема», «акула плывёт».

Поиск по словам (`searchPresets` в `packages/core/src/plan.ts`) учитывает:
- раздел библиотеки;
- прилагательные (ленивая → спокойная, тяжёлая → голем);
- прямые упоминания;
- тело: двуногому не достанется походка многоногого;
- карточку стиля.

Бег и силовой удар выбираются, только если о них просят. Чего в библиотеке нет, то честно попадает в `missing`. В отчёте `summary` для каждого клипа указаны выбранный пресет и ещё три варианта.

**Карточка стиля** (`style`) и **папка игры** (`godot`) запоминаются в проекте, повторять их не нужно. Поля карточки:
- `stylization`: realistic / cartoon;
- `role`: player / enemy / npc;
- `fps`, `genre`, `refs`, `notes`.

От карточки зависит выбор пресетов: мультяшному персонажу достаются движения Tools Up!, реалистичному — Witcher и TLJ, NPC — пресеты с читаемым телеграфом (заметным замахом перед ударом).

Повторный `make` с тем же именем клипа заменяет клип, так что править можно тем же вызовом: `--clips "walk=toolsup-heavy"`.

**Остановки:**
- в модели нет мешей (файл — только скелет);
- риг сомнительный: цепочек нет или тело не узнано. Тогда `make` рисует модель в `out/make-rig.png` и ждёт вызова с `--force`.

Длина разового клипа берётся из рецепта (`length`). Удар длится до открытия окна ввода, силовой заряд — целиком.

## Проверка, починка и критик

`make` сам проверяет клипы после сборки и чинит, что умеет. То же вручную:

```sh
pnpm af check --project out/baker                 # отчёт по всем клипам
pnpm af check --project out/baker --clip attack --fix true
pnpm af review.pack --project out/baker           # листы кадров для критика
```

**Что меряет код** (`packages/cli/src/checks.ts`). Всё — на настоящей коже модели, а не на костях. Кадров 31 со сдвигом фазы, чтобы разрыв не прятался между ними.

| проверка | брак | почему так |
|---|---|---|
| кожа | рёбра меша растянуты больше чем в 1,6 раза у > 0,5 % рёбер | сжатие в сгибе — не брак, растяжение — брак |
| пол | ноги уходят под пол глубже 1 % роста | пол — нижняя точка меша в покое |
| шов цикла | скачок на стыке больше 1 % роста и в 10 раз больше шага внутри клипа | |
| рывок | шаг за кадр больше медианного в 3 раза и больше 2 % роста (кроме ±0,1 с у удара) | |
| стопы скользят | персонаж идёт с естественной скоростью клипа, опорная стопа проезжает по полу больше 5 % роста за шаг; опора едет вперёд («лунная» походка) — брак; шаг медленнее 0,15 роста/с — топчется на месте | мерка — `gaitSlide` ядра, та же, что подгоняет шаг под скорость в Godot |
| пределы | кость упирается в предел больше 30 % клипа | |
| тайминг | удар игрока позже 0,35 с; замах врага короче 0,3 с; окно ввода нулевое | |
| длина | клип короче своих событий | |

**Починка** (`--fix true`) идёт по порядку, от структуры к силе:
1. Веса у суставов сглаживаются (`weights.smooth`). Результат остаётся, только если кожа рвётся хотя бы на треть меньше; иначе модель возвращается как была.
2. Стопы ставятся на пол IK и плоско (`clip.ground` с `flat`).
3. Слои, которые рвут кожу, ослабляются шагами ×0.7. Главный слой походки — не ниже ×0.35, таз и грудь на полу — не ниже ×0.5, чтобы походка не потеряла характер.
4. Удар рукой, который рвёт кожу при любой силе, заменяется тараном корпусом `body-ram` (`ram-npc` / `ram-player` по роли). Так бывает у колобков: руки короткие, мах ими рвёт меш. Замена делается, только если виновата именно рука.
5. Скользящую походку сначала чинит фиксация опорной стопы (`clip.ground --lock true`, ниже). Если её мало — у `waddle-walk` подбор фазы ног к тазу (`legPhase` — у пресетов верная фаза разная), а если мало — меньше рыскания таза и шире мах ног. Шаг при этом не должен выродиться в топтание, кожа не должна стать хуже.
6. Нулевое окно ввода получает `tail` 0,3 с, клип удлиняется (`clip.set --fit true`).

**Отчёт словами и советы.** У каждого клипа есть строка `text` в единицах игры: скорость шага в м/с, проезд стопы и провал в мм, кожа, шов. У каждой непочиненной находки есть `advice`: что поменять и что тогда станет. Совет — не догадка, а проба (`packages/cli/src/advice.ts`):
- кандидаты — по одной ручке: вес слоя ×0.7 / ×0.5, параметр рецепта ×0.8 / ×1.25 (у петли с `period` длина клипа меняется вместе с ним), ступни на пол;
- каждого меряем той же меркой, что и проверку; в совет идут два лучших, сначала параметры, потом ослабление слоёв;
- правка, после которой кожа рвётся сильнее, в совет не попадает;
- у совета есть готовые команды `steps` — агент применяет их как есть, и получается обещанное число (это проверяет тест).

Пример: «legSwing 30 → 24° (мах бедра — меньше) → стопа проезжает 5.4 % роста (78 мм) за шаг». Если кожа рвётся при любой ручке движения, совет — сгладить веса модели. Идея — из отчёта Motion Lab в ActionForge, но там совет только к скольжению стоп.

**Критик** судит то, что числом не измерить: силуэт, вес, читаемость, характер. `review.pack` собирает в `out/review/` листы кадров (спереди в три четверти и в профиль, ≈6 кадров на секунду, кадр удара — всегда) и `review.json` (карточка стиля, клипы, ключи, отчёт проверок). Критика запускает агент: отдельный субагент с промптом `critic/CRITIC.md`. Он только судит и отвечает JSON с вердиктом, оценками 1–5 и замечаниями с кадрами. `make` собирает пакет сам, когда проверка что-то нашла (`--review true` — всегда). Критерии и их источники — `docs/review-criteria.md`.

## Веб-интерфейс

```sh
pnpm web                     # http://localhost:5178/?dir=projects/fish-demo  (порт — PORT=…)
pnpm web:shot 't=0.3&paused=1&bone=spine_5' out/web/t0.3.png   # скриншот без окна (headless Chromium по CDP)
AF_URL=https://… pnpm web:shot x out/web/other.png              # снять любую страницу (AF_WAIT_MS, AF_EVAL — JS перед снимком)
```

- **Своя модель**: перетащите FBX, GLB, glTF (одним файлом) или DAE в окно или нажмите «Загрузить модель».
  Сервер (`POST /api/upload` → команда `project.new`) импортирует её через Blender, распознаёт скелет и открывает
  новый проект в `out/uploads/<имя>` (в git не попадает). Без скелета со скином — понятная ошибка, полупроект удаляется.
  Из CLI то же самое: `pnpm af project.new --file ~/Downloads/hero.fbx --project out/uploads/hero`.
- **Библиотека** (слева): все пресеты с поиском, разделами по типу движения и происхождением (Witcher 3, DREDGE, TLJ…).
  На карточке — кривые главной кости за цикл, их считает само ядро. Тип тела берётся из `rig.detect` без записи,
  поэтому четвероногому первыми показываются походки, пауку — ноги; то, на что не хватает цепочек, скрыто.
- **Примерка**: клик по карточке — клип с этим движением сразу играет на вашей модели, на диск ничего не пишется
  (`POST /api/preview`: те же команды на копии проекта). Ползунки во время примерки тоже правят копию.
  «Применить» (Enter) повторяет все шаги командами ядра, Esc — отмена. Походки ставят лапы на пол (`clip.ground`).
- **Слои** одного рецепта и пресета (лапы паука, крылья) собраны в группу: общий параметр правится у всех сразу.
  Слой можно выключить (`layer.set`, вес 0) или убрать (`layer.remove`), клип — удалить (`clip.remove`).
- **Вьюпорт**: ракурсы (F, 1–3), скелет, каркас, пол с тенью, гизмо осей. **Время**: вкладки клипов, кадр назад/вперёд,
  по кругу, скорость ×0.1…×2, линейка кадров с метками событий рецептов. Горячие клавиши — по «?».
- **Веса** (вкладка справа): модель красится тепловой картой выбранной кости (синий 0 → красный 1), кистью —
  добавить, убрать, сгладить; клик с Shift или Cmd по модели выбирает кость под курсором, Cmd+Z — отмена мазка.
  Анимация не останавливается: правишь вес прямо в шаге или в примерке из библиотеки. «Сохранить» пишет веса в glb
  модели (`/api/weights`, первый раз исходник ложится рядом — `<модель>.orig.glb`), «Вернуть исходные» — обратно.
  Правка веса одной кости — `setBoneWeight` в ядре: остальные кости делят остаток пропорционально, сумма 1.
- **Простой режим** (по умолчанию): справа — 3–5 главных ручек рецепта клипа (`RecipeDef.main`) и «Проверить / Починить» (та же `check`). Слои, ключи, цели, пределы и веса — под переключателем «Расширенное». «В Godot» — `publish`: glb в `out/` и копия в папку игры.
- **Скачать GLB** — все клипы, запечённые в glb (`/api/download`), для Godot, Blender и других движков.
- **График** (кнопка у таймлайна или K): кривые каждой конечности за клип — вверх-вниз, вперёд-назад, вбок, сгиб
  колена/локтя, высота стопы над полом. У каждой — размах в см или градусах, полосы опоры стоп, линия времени;
  клик и перетаскивание по графику перематывают, наведение подсвечивает цепочку во вьюпорте. Считает ядро
  (`motionGraph`: конец цепочки по осям тела, сгиб, опора по правилу `lockPlan`). **Следы** (меню «глаз» или T) —
  траектории стоп, кистей и таза за цикл прямо во вьюпорте.
- **Правка кривых** (как Late / Amount / Step у ActionForge): клик по имени конечности в легенде графика — ползунки
  «Сдвиг» (по фазе, доля цикла), «Размах» (вокруг среднего за цикл: 0 — замереть в среднем, 2 — вдвое шире) и
  «Задержка» (каждая следующая кость цепочки позже — волна по хвосту, спине, руке). Alt + тянуть кривую на графике:
  вбок — сдвиг, вверх-вниз — размах. Это команда `layer.shape` на всех слоях-рецептах цепочки:
  `pnpm af layer.shape --clip walk --chain pelvis --late 0.1 --amount 1.5 --project $P` (`--step 0.05`, `--reset true`).
  Считается и в ядре, и в аддоне Godot (сверка `live.verify`).
- **Ключи на следах**: в режиме «Поза» (P) с включёнными следами схватите след стопы или кисти — клип перейдёт в этот
  момент, а конец цепочки потянется, как сустав; отпустили — ключ позы в момент точки следа. Ключи позы видны на
  следе белыми метками. Слой позы держит позу между ключами — чтобы правка была местной, поставьте ключи и до, и после.

Поза во вьюпорте считается вживую ядром (`poseAt`) на каждом кадре; любое действие в интерфейсе — команда ядра
через `POST /api/command` (тот же `call()`, что у CLI). Если `animforge.json` поменять снаружи (`pnpm af key.set …`),
открытая страница перечитает проект сама (SSE `/api/events` + `fs.watch`).
Параметры адреса: `dir`, `clip`, `t`, `paused=1`, `bone` (кость или цепочка), `skeleton=0`, `left=bones`.

## Устройство

- `packages/core` — модель проекта, рецепты, кривые, вычисление позы, запекание в glTF, реестр команд. Работает и в браузере, и в Node.
- `packages/cli` — адаптеры Node: файлы, Blender, Godot; CLI `af`.
- `apps/web` — веб-интерфейс: Vite + React + three.js, dev-сервер `server.ts` с API поверх адаптеров CLI.
- `bridge/blender` — шаблоны тел (авториг-заготовки), импорт чужих моделей, отрисовка кадров.
- `godot/verify` — проверка экспорта в Godot 4.5.
- `library/presets` — пресеты рецептов; у каждого записано происхождение (из каких замеров взят).
- `research/` — контур «Исследование» (приватный): что извлечено из игр, в библиотеку не попадает.
- `projects/` — проекты анимации (`animforge.json` — текст, удобно править и смотреть в git).

## Живые рецепты в Godot

`af publish` (и `make`) кладёт рядом с glb файл `<имя>.af.json`: скелет в позе покоя, цепочки, пределы суставов и клипы со всеми слоями. Узел `AnimForgeLive` из аддона считает по нему позу прямо в игре, каждый кадр, без запечённых ключей.

```gdscript
var live := AnimForgeLive.new()          # модификатор скелета: ребёнок Skeleton3D модели
skeleton.add_child(live)
live.data_file = "res://chars/baker.af.json"
live.play("walk")
live.set_knob("waddle-walk", "period", 0.62)       # шаг медленнее — сразу, без перевыгрузки
live.animforge_event.connect(func(name, clip): if name == "hit": deal_damage())
```

- **Ручки в инспекторе.** Главные параметры рецептов клипа (`RecipeDef.main`) лежат в группе «Ручки» и сохраняются в сцене. В редакторе клип играет сразу, ползунок меняет его на глазах.
- **События** (`hit`, `whoosh`, `window_open`…) приходят сигналом `animforge_event(name, clip)`. Если задан `event_target`, у него тоже вызывается `animforge_event`. Конец разового клипа — сигнал `finished`.
- **Игровые связки** (группа «Игра» в инспекторе):
  - `match_speed` + `body` (CharacterBody3D — по `velocity`, другой узел — по сдвигу за кадр) или `move_speed` из кода: шаг идёт с такой скоростью, чтобы опорная стопа стояла на месте. Естественная скорость клипа — `natural_speed()`: с какой скоростью опорная стопа уезжает назад. Если она едет вперёд («лунная» походка), подгонки нет, и в консоли предупреждение — такую походку надо чинить.
  - `terrain`: лучи вниз от каждой стопы (`terrain_mask`, `terrain_reach`). Тело опускается к нижней опоре, остальные стопы поднимает IK — склоны и ступеньки.
  - `look_target`: взгляд на узел. Работает через aim-констрейны клипа, а если их нет — через шею и голову (`look_weight`). `set_target(id, точка)` — цель любого констрейна клипа (рука к рычагу).
  - `live_secondary` (по умолчанию включено): уши, хвост, колпак раскачивает настоящее движение персонажа в мире — разворот, остановка, прыжок, — а не запись клипа. Пружина та же, что в ядре; ускорения — по трём последним кадрам. На месте она сходится с записью (расхождение 0,8° при размахе 17°). Состояние живёт по цепочкам и переживает смену клипа.
  - Демо: `godot/sandbox/demo/secondary_demo.tscn` — два рабочих рывками разворачиваются и подпрыгивают: слева уши по записи, справа живые.
  - Демо: `godot/sandbox/demo/live_demo.tscn` — рабочий идёт с меняющейся скоростью по склону и ступенькам и провожает взглядом мяч.
- **Что считается вживую:** всё, что в редакторе. Рецепты, ключи, позы, выравнивание рук, пределы суставов, пол с IK и плоской стопой, IK, взгляд, копия поворота и вторичная динамика.
- **Скорость:** 0,1–0,6 мс на позу у демо-персонажей. IK руки с пределами к недостижимой цели — до 10 мс: перебор начал и CCD.

Код — копия ядра: `live/af_core.gd` (evaluate.ts и limits.ts) и `live/af_recipes.gd` (recipes.ts). Совпадение проверяют две команды:
- `pnpm af recipes.verify` — каждый рецепт на всех пресетах и значениях enum, около 660 тыс. точек, до 10⁻¹³;
- `pnpm af live.verify` — позы всех клипов демо-проектов в Godot без окна, кость в кость с ядром. Плюс клип, где есть всё остальное: ключи, позы, IK с пределами и без, взгляд, зеркальная копия, пол `contact`. Ещё рельеф (та же функция пола в ядре и в Godot — `LiveOpts` в evaluate.ts), цели из игры и естественная скорость. И сам узел в сцене: стопа встаёт на ступеньку лучом, темп ×2 при двойной скорости, голова поворачивается к цели, живые уши на месте сходятся с записью, после разворота отклоняются и затухают.

Допуск сверки — 0,5°. Vector3 и Quaternion в Godot хранят float32, и у почти прямой ноги угол через arccos теряет до 0,3°. Ошибку выбора (другую ветку IK) сверка ловит.

## Каналы, пол и вторичная динамика

Повороты бывают двух видов. `lateral | vertical | roll` идут по осям цепочки, а `pitch | yaw | bank` — по осям тела
(наклон вперёд вокруг бока, поворот вокруг верха, крен вокруг «вперёд»). Рецепты ходьбы и ударов пишутся в осях тела, поэтому одинаково
работают на любом риге, как бы ни были повёрнуты локальные оси костей. Есть ещё сдвиги `move_up | move_forward | move_side`
(в метрах, по осям тела: up = `project.up`, forward = `project.forward`, по умолчанию +Z) и масштаб `scale_up | scale_forward | scale_side`.
Масштаб попадает на ту ось кости, что ближе к нужному направлению. Всё это экспортируется в glTF и сверяется в Godot (`af verify`).

- `af clip.ground --clip walk --bones foot_l,foot_r --mode floor --ik true` ставит ступни на пол после всех слоёв.
  Режим `contact` прижимает тело к полу, режим `floor` не даёт провалиться, `ik` сгибает колено (двухзвенная IK), а не двигает тело.
- Рецепт `jiggle` — уши, усы, хвосты по движению родителя: маятник с пружиной, у пресетов параметры DynamicBone из Tools Up!.
- Рецепт `waddle-walk` — ходьба вразвалку Tools Up! (подскок таза взят покадрово), `blink` — моргание масштабом,
  `compass-step` — шаг-циркуль Biped.
- `af video --clip walk1 --out out/walk.mp4 --view front_3q` — видео клипа; `sheet --view front|profile|front_3q` — виды для персонажей.
- Шаблоны тел: `fish | snake | tentacle | quadruped | biped | worker`.

## Стиль походки

```sh
pnpm af clip.gait --project out/baker --clip walk --style sneak                 # stroll | brisk | heavy | sneak
pnpm af clip.gait --project out/baker --clip walk --gait '{"speed":1.2,"bounce":0.5,"posture":8}'
```

Ручки — поверх любых слоёв цикла, от рецепта не зависят (`applyGait` в evaluate.ts, то же в аддоне Godot):

| ручка | что делает |
|---|---|
| `speed` × | частота шагов растёт как speed^0.6, длина шага — как speed^0.4. Так у 13 наборов The Witcher при переходе от шага к бегу: скорость ×1.98, частота ×1.54, шаг ×1.32. Длину клипа команда меняет сама |
| `bounce`, `sway`, `arms`, `lift` × | подскок таза, его раскачка, мах рук, сгиб колена в переносе — каждый вокруг своего среднего за цикл. ×0 — таз на средней высоте, а не в покое; рука с постоянным отводом остаётся отведённой |
| `width` ° | ноги наружу |
| `lower` | таз ниже на долю роста (нужен `clip.ground` с `ik`) |
| `lean` ° | корпус вперёд вместе с головой |
| `posture` ° | грудь вперёд, голова обратно — смотрит прямо |

Стили (`GAIT_STYLES`) — наборы ручек, на глаз. Идея — пресеты Motion Lab в ActionForge. Демо — `godot/sandbox/demo/gait_demo.tscn`.

## Утилиты клипа: зеркало, задом наперёд, на месте

```sh
pnpm af clip.mirror --clip walk --as walk_mirror --project $P     # зеркальная копия (без as — переключить у клипа)
pnpm af clip.reverse --clip hammer --as hammer_back --project $P   # задом наперёд, события — в зеркальные моменты
pnpm af clip.inplace --clip run --axes forward,side,yaw --project $P   # снять ход корня; --off true — вернуть
```

- **Зеркало** — последняя стадия позы: поворот каждой кости в мировых осях покоя отражается через плоскость
  симметрии тела и отдаётся её паре, сдвиги отражаются. Пары (`mirrorPairs`): цепочки `x_l ↔ x_r` кость в кость,
  потом имена с метками сторон (`_l/_r`, `Left/Right`, `.L/.R`, `l_/r_`), потом дети уже найденных пар по порядку
  (стопа под голенью, пальцы под кистью). Кость стоит там, где стояла её пара, отражённая, — до 2 мм у рабочего.
- **Задом наперёд** — время клипа идёт от конца к началу; вместе с `travel.reverse` отменяют друг друга.
  Вторичная динамика (уши, хвост) считается вперёд по времени уже по перевёрнутому движению — она не обратима.
- **На месте** — с таза и костей над ним снимается ход клипа «конец − начало» по выбранным осям тела, равномерно
  за клип: корень перестаёт уезжать, а качание внутри шага остаётся. Для клипов с ходом корня (ключи, импорт).
- В редакторе — меню «⋯» у таймлайна (копии и переключатели, плюс догоняющее движение) и «Камера за персонажем»
  в меню «глаз». Всё это считается и в аддоне Godot (`live.verify`; пары зеркала приходят в `.af.json`).

## Сложение по частям тела, пропсы, позы кисти

```sh
pnpm af clip.compose --clip walk_hit --from hammer --chains arm_r,chest --project $P   # ноги идут, рука бьёт
pnpm af prop.attach --id sword --hand r --file ~/Downloads/sword.glb --rot 90,0,0 --project $P
pnpm af prop.attach --id stick --hand r --size 0.04,0.04,0.6 --offset 0,-0.05,0.15 --project $P   # заглушка
pnpm af hand.pose --clip walk --side both --pose fist --project $P   # fist | relaxed | open | point | grip | thumbs_up
pnpm af hand.pose --clip strike --side r --pose grip --t 0.3 --project $P   # ключ в момент: от позы к позе
```

- **`clip.compose`** — цепочки клипа берутся из другого клипа: его рецепты на этих цепочках, ключи и позы их
  костей (`mode=add` — поверх своих). Данные, а не новая стадия: экспорт и аддон Godot считают как обычно.
- **Пропы** — свой glb или коробка-заглушка на кости (`hand l|r` — кисть по стандартным именам, у руки-варежки —
  последняя кость руки). Смещение и поворот — в мировых осях позы покоя, размер — в метрах при любом масштабе кости.
  В экспорте проп — узел-ребёнок кости (`prop_<id>`): Godot делает из него `BoneAttachment3D`, Blender и FBX —
  дочерний объект; во вьюпорте редактора проп виден сразу (`/api/prop`).
- **Позы кисти** — ключ слоя позы `hands`: пальцы — дети кисти с потомками (по именам Thumb/Index/Middle/Ring/Pinky,
  иначе большой — ближе всех к запястью), сгиб — к ладони: нормаль ладони = направление кисти × «поперёк» (к большому
  пальцу), у правой — со сменой знака. Углы — на глаз. Проверено на Mixamo Xbot: в кулаке кончики пальцев ниже кисти
  (в T-позе ладонь вниз) и втрое ближе к запястью, кисти зеркальны.

## Догоняющее движение (follow-through)

```sh
pnpm af clip.follow --clip walk --lag 0.1 --bounce 0.3 --loosen 0.7 --project $P   # без аргументов — убрать
```

Грудь догоняет таз, голова и руки — грудь (как Follow-through у ActionForge: Lag, Bounce, Loosen). Мировой поворот
ведущей кости (таза, потом верха корпуса) проходит через пружину ω = 2/lag с затуханием ζ = 1 − 0.85·bounce;
корень следующего звена получает loosen·(пружина − ведущий): при loosen 1 он поворачивается за ведущим целиком
с запаздыванием и перелётом, при 0 — как без follow. Голова и руки догоняют уже запоздавшую грудь. У цикла берётся
установившийся проход (пятый), у разового клипа пружина стартует с покоя. Стадия — после слоёв и пола, до вторичной
динамики; считается и в аддоне Godot (`live.verify`). На тазе, который только рыщет, грудь при lag 0.1 с отстаёт
примерно на 0.1 с, голова от груди — так же.

## Фиксация опорной стопы

```sh
pnpm af clip.ground --project out/baker --clip walk --bones foot_l,foot_r --mode floor --ik true --flat true --lock true
```

В игре персонаж идёт со скоростью клипа v, значит опорная стопа в клипе на месте должна уезжать назад ровно со скоростью v и по прямой. Рецепт так не умеет: мах — это поворот бедра, поэтому стопа в опоре идёт по дуге и с переменной скоростью. Отсюда и скольжение.

`ground.lock` строит план на клип (`lockPlan` в evaluate.ts, то же в аддоне Godot):
- **опора** — кадры, где стопа у пола и уезжает назад;
- **прямая «как надо»** — по наименьшим квадратам к тому, где стопа есть; в опоре стопа ставится на неё двухзвенной IK;
- **перенос** — поправка плавно переходит от конца одного шага к началу следующего, а стопа держится над полом. У рецептов конец переноса часто идёт ниже пола, и IK пола тащила стопу по нему вперёд;
- **длина ноги** — если ноге не хватает длины (больше 0.97), таз опускается со сглаживанием, но не больше чем на 1 % роста. У коротких толстых ног рабочего при большем опускании бедро уходит в пол.

Скорость опоры считается как среднее, а не медиана: от шума float32 медиана в Godot сдвигалась на 2 %. Скольжение у спокойной ходьбы и у Геральта — 1.8–4.3 % → 0–0.5 % роста за шаг, скорость шага та же. «Лунную» походку и топтание фиксация не чинит: там стопа в опоре едет не туда, это дело фазы ног.

## 8 направлений из одной ходьбы

```sh
pnpm af clip.directions --project out/baker --clip walk          # walk_fwd, _fwd_l, _left, _back_l, _back, _back_r, _right, _fwd_r
pnpm af clip.directions --project out/baker --clip walk --face travel   # всё тело поворачивается по ходу
```

Клип направления — копия прямой ходьбы с полем `travel` (команда `clip.travel` ставит его вручную). Ядро (`applyTravel` в evaluate.ts, то же в аддоне Godot):
- у каждой цепочки `leg_*` мах бедра поворачивается вокруг вертикали (сопряжение R·m·R⁻¹): стопа идёт вбок, а колено гнётся как обычно, вперёд — так и у людей при стрейфе;
- таз доворачивает к ходу на `hips`, грудь возвращает долю `chest`, голова — долю остатка `look`;
- стопы смотрят на `feet`, ноги отводятся на `width`, размах маха — `stride`;
- назад — та же ходьба наоборот во времени (`reverse`): подскок, крен и сгиб колена приходят в свои моменты шага. Без этого стопа ехала 9.7 % роста за шаг, с ним — 2.9 %.

Коэффициенты по углу — таблица `DIRECTIONS` (directions.ts). 90° и 180° измерены на 10 клипах The Witcher (research/directions.md): вбок таз 61°, грудь возвращает 0.24, стопы 0.76·θ, колея +2°, шаг ×0.9, **период тот же**. «Шаг короче, частота выше» из ActionForge в Witcher не подтвердилось. Диагонали — на глаз.

Плоскость маха `swing` подбирается замером: таз в рецептах ходьбы рыщет и кренится, это тоже возит стопы, и тело идёт не туда, куда машут ноги. `gaitHeading` меряет, куда тело идёт на самом деле, а секущие подгоняют `swing`, пока ошибка не станет меньше 0.5°. Назад-вбок пробуются два варианта, «ходьба наоборот» и «прямая, повёрнутая назад», и остаётся тот, где стопы меньше скользят.

Все направления — с той же фазы шага, поэтому в движке их можно смешивать. В Godot персонажа двигают по `travel_direction()` со скоростью `natural_speed()` (демо `godot/sandbox/demo/directions_demo.tscn`, `WALK=walk1` — вразвалку).


В архиве — файл на каждое направление, все вместе одним файлом, `<clip>_blendspace.tres` (AnimationNodeBlendSpace2D:
точка — куда идёт персонаж в его осях, `Vector2(вправо, вперёд)` как ввод джойстика, стойка `--idle` в центре,
`sync` включён) и README. Направлений в проекте нет — их делает `clip.directions` в памяти, проект не меняется.
В редакторе — меню «FBX» → «8 направлений — zip». Проверено в Godot (`godot/verify/blendspace_check.gd`): дерево из

### Доля опоры

`clip.gait` с `stance` (0.2…0.85) — какую часть цикла стопа стоит на земле: шаг ~0.6, бег ~0.35. Время слоёв ног
перекраивается кусочно-линейно: от касания (стопа дальше всего вперёд от бедра) опора идёт заданную долю цикла,
перенос — остаток, касание и отрыв остаются на своих местах цикла. План — по слою самой ноги (без таза и корпуса).
У четвероногих так же работают передние лапы (цепочки `arm_*`, кончик которых у пола). В редакторе — панель
«Походка» в простом режиме: стили stroll/brisk/heavy/sneak и ручки скорости, доли опоры, подскока, раскачки, маха
рук, подъёма стопы и наклона. Тест меряет долю по самой анимации (сколько цикла стопа идёт назад от бедра): 0.70 и
0.35 при заданных 0.7 и 0.35; аддон Godot считает то же (`live.verify`).

## Бой, события и вставки в idle

- `melee-strike`: удар или серия. Фазы: замах, взмах с пиком скорости за `hitLag` до контакта, доводка, возврат, окно на следующий ввод.
  Слои ставятся на роли `arm` (плечо→локоть), `core`, `pelvis`. Пресеты: стили Геральта, телеграфы NPC от собаки до голема, молоток Tools Up!.
- `body-ram`: таран корпусом — замах назад с задержкой, бросок тазом вперёд, контакт, откат за нейтраль и затухающий отскок. Второй слой — на голове: она гасит часть наклона корпуса и догоняет его, так что удар ведёт тело, а не голова. Пресеты `ram-npc` (замах читается заранее) и `ram-player` (отзывчивый). Для персонажей, у которых мах руками рвёт меш.
- `charge-release`: силовая атака — замах, удержание с пружинящим корнем, выпуск двумя ударами (`witcher-power`).
- События рецептов: `hit`, `whoosh`, `effort`, `trail_on/off`, `window_open/close`.
  Посмотреть их: `af clip.events --clip combo`. При экспорте они пишутся в extras анимации и в `<glb>.events.json`.
  В Godot их подключает `AnimForge.attach_events(player, "res://…events.json", self)`, дальше игра получает вызовы `animforge_event(name, clip)`.
- Вставки в idle по шансу и кулдауну (Witcher, TLJ): `AnimForge.idle_variety($AnimationPlayer, "witcher-geralt")`. Пресеты лежат в `library/idle/`.
- `af tweens.verify` проверяет аддон целиком: твины, события и вставки в idle.
- Шаблоны: детали тела слушаются только своих костей (`bodykit.restrict_weights`), поэтому взмах руки не мнёт туловище и голову.

## Экспорт в FBX и на стандартные скелеты

```sh
pnpm af export --out out/hero.fbx --names unreal --units unreal --project $P   # FBX для Unreal, кости pelvis, thigh_l…
pnpm af export --out out/hero.fbx --names mixamo --units unity --project $P    # для Unity / Mixamo: mixamorig:Hips…
pnpm af export --out out/hero.glb --names mixamo --project $P                  # glb тоже можно переименовать
pnpm af verify --out out/hero.fbx --names unreal --units unreal --project $P   # сверка FBX в Godot
```

- **Имена** (`--names`, `standardNames` в ядре) — по цепочкам проекта: таз, позвоночник и грудь
  (`Spine, Spine1…` / `spine_01…`), шея, голова, руки (три кости — первая ключица), ноги; кисть, стопа и носок —
  главные дети последних костей. У Unreal кость над тазом — `root`. Кости вне цепочек (пальцы, уши) остаются со
  своими именами, имя, уже занятое другой костью, не ставится. С такими именами авто-сопоставление движка
  (IK Retargeter в UE5, Humanoid в Unity, ретаргет Mixamo) узнаёт скелет само. Скелетов Epic и Adobe мы не возим —
  только имена.
- **FBX** собирает Blender из того же glb (`bridge/blender/export_fbx.py`): скин, каждый клип — тейк со своим именем.
  Единицы `--units`: `blender` (по умолчанию; метры, Y вверх — так же для Godot и Maya), `unity` (масштаб вшит
  в файл, объект в Unity с масштабом 1), `unreal` (то же, Z вверх, скелет называется `Armature`, чтобы UE не делал
  из него лишнюю кость над `root`).
- **Проверка** (`verify` с `.fbx`): Godot читает FBX сам (ufbx) и переводит единицы и оси файла в метры. Сверяются
  положения всех суставов в мире на трёх моментах каждого клипа с ядром, допуск 0.5 % роста — так ловятся и оси,
  и масштаб пресета, и выпавшие тейки. Повороты не сверяем: Blender меняет оси костей в rest, а движение то же.
  У рабочего во всех пресетах расхождение 0.000 %. В самих Unreal и Unity файлы не открывали — их на этом маке нет.
- С чужими именами `.af.json` для живых рецептов не пишется: аддон Godot ищет кости по именам проекта.

## Живое превью в библиотеке

Наведите на карточку пресета или готового клипа — справа появится окошко со скелетом **вашей модели** в этом
движении (вид на три четверти, по кругу). Сервер (`/api/stick`) делает те же шаги, что примерка, на копии проекта и
отдаёт кадры суставов в 2D (`stickAnim`, packages/cli/src/stickpreview.ts); кэш — по проекту и движению, ответ
за десятки миллисекунд. Ничего не рендерится заранее и не хранится: превью всегда на том теле, что открыто.

## Чужие модели: перенос на любой скелет

```sh
pnpm af model.import --file Xbot.fbx --out assets/model.glb --project $P   # FBX, glTF, OBJ, DAE → glb со скином
pnpm af rig.detect --project $P            # цепочки, «вперёд», выравнивание рук
pnpm af clip.add --name walk --duration 1 --project $P
pnpm af recipe.rig --clip walk --recipe waddle-walk --preset toolsup-worker --project $P   # слой на каждую роль
pnpm af clip.ground --clip walk --bones LeftFoot,RightFoot --mode floor --ik true --project $P
```

- `rig.detect` узнаёт кости по именам: Mixamo, Unreal, Unity, Rigify, 3ds Max Biped, числовые префиксы.
  Если имён нет, строит цепочки по геометрии. Направление «вперёд» берёт по меткам L/R, а без них — по носкам.
- Руки, которые в rest отходят от «вниз» больше чем на 30° (T- и A-поза), записываются в `project.align`.
  Перед всеми слоями их опускает вниз с отведением 8°, так махи рецептов начинаются из одной позы у любой модели.
- Масштаб узлов учитывается везде: у FBX корень часто в 0.01 (сантиметры), а сдвиги, IK и пол считаются в метрах мира.
- `model.import` сажает кожу на свои кости. У моделей, вытащенных рипером из сцен-витрин, меш и скелет висят под разными узлами.
  Импорт пробует оба толкования вершин (как рисует Blender и как движок) и берёт то, где вершины ближе к своим костям.
- «Глаза» (`sheet`, `video`) рисуют кожу по спецификации glTF, так же как Godot: позу считает ядро, скиннинг — `packages/cli/src/skin.ts`,
  а Blender только рисует треугольники. Импортёр Blender для этого не годится: у таких моделей он показывает кожу не там, где кости.
  Камера вписывает персонажа во всех позах клипа (`--dist 1`) и смотрит ему в лицо по `project.forward`.
- `af verify` сверяет кости в Godot. Godot заменяет `:` в именах костей на `_` (`mixamorig:Hips`), и проверка это учитывает.
  Если кость не найдена, проверка падает, а не сравнивает с нулём.
- Проверено на Xbot (Mixamo, T-поза), Worker и DeliveryGuy (Tools Up!, A-поза, сцена-витрина) и April (The Longest Journey).

### Перенос готового клипа с другого персонажа (`clip.copy`)

```sh
pnpm af clip.copy --from projects/worker-demo --clip walk_april --project $P        # один клип
pnpm af clip.copy --from projects/worker-demo --clip '*' --project $P               # все
pnpm af clip.copy --from out/hero --clip hammer --as hammer_hero --replace true --project $P
```

- Слои рецептов адресуют цепочки по ролям и машут в осях тела — они переносятся как есть. Слой цепочки, которой
  у цели нет (уши рабочего у Xbot), выпадает и попадает в `dropped`.
- Кости ключей, поз, целей и пола сопоставляются по ролям: цепочка с тем же именем — кость на том же месте
  (у разной длины — пропорционально), стопа, кисть, носок и root — по стандартным именам (`standardNames`),
  остальное — по совпадающему имени.
- Сдвиги (`move_*`, сдвиги поз, точки целей) масштабируются по росту скелета и поворачиваются по осям тела. Повороты поз
  пересчитываются через мир позы покоя: поза в осях одной кости становится той же позой в осях другой.
- IK руки-варежки (`end`) у цели с кистью становится IK кисти, и наоборот.
- Рабочий (1.3 м) → Xbot (1.8 м): масштаб ×1.39, кисть по IK в пределах 2 см от перенесённой цели, плечо в позе —
  то же направление в осях тела (расхождение 3°). Те же углы шага на длинных ногах дают другую скорость и иное
  скольжение: у Xbot ходьбы без фиксации скользят на 13–25 % (родной рецепт на нём — тоже, 17 %). Поэтому после
  переноса походки — `check --fix`, он ставит `ground.lock`: с ним скольжения 0.
- Пределы суставов (`limits`) — у проекта, а не у клипа, и не переносятся.

- Перенос — мировыми поворотами от позы покоя, в осях тела цели. Разную позу покоя (T у источника, A у цели) снимает

  путь таза источника, умноженный на отношение ростов; ход корня (`*_RM`) уходит в таз. Выравнивание рук

- Цикл узнаётся по «loop/idle/cycle» в имени или по совпадению первого и последнего кадра; `--loop true|false` — вручную.
- FBX, BVH и DAE идут через Blender в glb со всеми дублями; концевые кости FBX не выбрасываются — у своих моделей
  это настоящие кости (кисть-варежка, ухо). У источника `--author` и `--license` записываются в слой (`source`).
- Пределы суставов действуют и на основу: если клип упирается в них, `limit.clear` или подправьте пределы.

## Ограничения (констрейны): диапазон движения костей

Колено не гнётся вперёд, локоть — назад, шея не крутится на 360°, даже если рецепт, ключ или перенос
с чужого скелета этого хотят. Поворот кости раскладывается на кручение и два изгиба (swing-twist), каждый угол
обрезается по своему диапазону. Оси — те же, что у ключей: у кости цепочки `lateral` / `vertical` / `roll`, у
корпуса и головы `pitch` / `yaw` / `bank`. Углы меряются от выровненной позы покоя (рука, опущенная из T-позы,
стоит в нуле). Пределы применяются до пола и IK и ещё раз после вторичной динамики — экспорт тоже обрезан.

```bash
pnpm af limit.auto --project projects/worker-demo                 # анатомия: колени, локти, шея, голова
pnpm af limit.set --bone leg_l_1 --axis vertical --min -150 --max 0
pnpm af limit.set --chain tail --axis lateral --min -40 --max 40  # каждой кости цепочки
pnpm af limit.fit --chain arm_r --margin 5                        # размах «как в клипах» + запас
pnpm af limit.clear --bone head --axis yaw                        # без аргументов — снять всё
```

`limit.auto` сам находит, в какую сторону гнётся сустав: крутит среднюю кость на 20° и смотрит, куда ушёл конец
(стопа — назад, кисть — вперёд); ось сгиба — `vertical` у висящей ноги и `lateral` у руки в T-позе. Диапазоны
0…150° колена и 0…145° локтя — анатомическая норма человека, ±8° вбок и ±15° кручения — на глаз.

В редакторе — вкладка «Пределы»: у выбранной кости ползунки диапазона по осям, синяя метка — где кость сейчас
в клипе (без ограничения), красная — упёрлась; во вьюпорте упёршиеся кости отмечены красными точками.

## Цели: IK, взгляд и копия поворота

IK — кисть или стопа тянется к точке: взять предмет, опереться о стену, поставить ногу на ступеньку. Сгибаются две
кости над кончиком (плечо и локоть, бедро и колено), плечо и таз остаются на месте; до недостижимой цели рука
вытягивается в её сторону. Взгляд — голова и шея поворачиваются на цель, поворот делится между ними поровну.
Цель — точка, кость (смотреть на свою руку) или точка с ключами по времени (провожать взглядом, тянуться за
движущимся). Считается после слоёв и пола, до вторичной динамики; пределы суставов действуют и на цели —
голова не повернётся на 180°, локоть не вывернется. Экспорт запекает результат.

```bash
pnpm af ik.add --clip walk --chain arm_l --target 0.2,0.9,0.4 --project out/demo       # кисть к точке
pnpm af ik.add --clip walk --chain leg_r --target 0.1,0.3,0.3 --pole 0.1,0.5,2           # колено смотрит вперёд
pnpm af aim.add --clip walk --target -0.6,1.0,0.8 --project out/demo                    # шея + голова на точку
pnpm af aim.add --clip walk --targetBone hand_l --id look_hand                          # смотреть на свою кисть
pnpm af constraint.key --clip walk --id aim --t 1.9 --target 0.7,1.0,0.8                # цель поехала
pnpm af constraint.set --clip walk --id ik_arm_l --weight 0.5                           # полпути от анимации к цели
pnpm af constraint.remove --clip walk --id aim
```

Копия поворота — кость повторяет движение другой: второе ухо за первым, хвост за тазом, левая рука зеркально за
правой. Копируется движение источника от его позы покоя (выравнивание из T-позы не в счёт) и добавляется поверх
своей анимации; множитель −1 — в обратную сторону, 0.5 — вполовину. Пружины вторичной динамики считаются потом и
не копируются.

```bash
pnpm af copy.add --clip walk --chain ear_l --sourceChain ear_r --mirror true   # цепочки — кость к кости
pnpm af copy.add --clip walk --bone tail_0 --source pelvis --weight -0.5       # хвост гасит качание таза
```

У руки-варежки без кисти тянется конец предплечья (продолжение на длину плеча). В редакторе — вкладка «Цели»:
кнопки «IK: рука л / нога п / Взгляд» ставят цель там, где кончик сейчас, цель — шарик на модели (IK бирюзовый,
взгляд сиреневый), выбранную тащат стрелками; у цели с ключами перетаскивание ставит ключ в текущем кадре.
Сила, выключение, сторона сгиба (вперёд, назад, вверх, вниз) — в строке цели.

## Позинг: тянуть модель мышью

Режим «Поза» (кнопка с ладонью на панели вьюпорта или клавиша P): суставы — точки на модели, у костей без
дочерних (кисть-варежка, кончик хвоста, ухо) — точка на их конце, длина конца измеряется по коже. Схватили и тянете —
сгибаются N костей над схваченной (выбор рядом с кнопкой: 2 — рука или нога, 3–4 — с ключицей и корпусом, 8 — весь
хвост). Пределы суставов учитываются прямо при подборе позы: если локоть упёрся, догибается плечо, а не обрезается
поза. Отпустили — поза пишется ключом в текущий кадр (слой «pose»: между ключами повороты интерполируются
плавно, ключ посреди старых сохраняет то, что там было). Таз переносит тело целиком: закрепите ступни
(Alt+клик по суставу — IK-цель в текущей точке) и тяните таз вниз — персонаж присядет, колени согнутся сами.
«Сбросить» — убрать ключ позы в кадре.

```bash
pnpm af pose.reach --clip walk --t 0.5 --bone hand_l --target 0.4,1.3,0.3            # кисть в точку, 2 кости
pnpm af pose.reach --clip walk --t 0.5 --bone tail_7 --target 0,0.6,-0.5 --length 8  # весь хвост
pnpm af pose.reach --clip walk --t 0.5 --bone hips --target 0,0.8,0 --length 0       # таз вниз — присесть
pnpm af ik.add --clip walk --chain arm_l --target 0.6,1.1,0.4 --length 5             # IK-цель с корпусом
pnpm af pose.clear --clip walk --t 0.5
```

Решатель — CCD по цепочке с пределами внутри шага; у шарнира (локоть, колено с пределом) точное начало — сгиб
вокруг его оси, затем поворот основания, локоть остаётся ближе к тому месту, где был в анимации; потом ещё
несколько начал, берётся поза, где кончик ближе к цели.

### Слои поз и зеркальная поза

У каждого слоя поз в панели слоёв — **M** (выключить, слой молчит, но ключи целы), **S** (соло: звучит только
этот слой поз, рецепты и ключи кривых остаются) и **вес** 0…1 — доля поворотов и сдвигов позы (кватернион
масштабируется по углу, сдвиг — линейно). Вес есть и у слоёв ключей кривых, выключение — у любого слоя.
Кнопка **⇋ X** в режиме позы — зеркальный позинг: тянете левую руку, правая повторяет отражённо через плоскость
симметрии тела (корпус на оси тела при этом не гнётся, чтобы не ломать симметрию). **«Отразить»** — переписать ключ
позы кадра его зеркальной копией: левая ↔ правая.

```bash
pnpm af layer.mute --clip walk --layer pose            # выключить; --off — включить обратно
pnpm af layer.solo --clip walk --layer pose2
pnpm af layer.set  --clip walk --layer pose --weight 0.5
pnpm af pose.reach --clip walk --t 0.5 --bone hand_l --target 0.4,1.3,0.3 --mirror
pnpm af pose.mirror --clip walk --t 0.5
```

Всё это считает и аддон Godot (`af_core.gd`) — сверка `live.verify` совпадает с ядром.

## Авториг: модель без скелета

```sh
pnpm af model.autorig --file ~/Downloads/statue.obj --project out/uploads/statue   # → assets/model.glb со скином
pnpm af project.new --file ~/Downloads/statue.obj --project out/uploads/statue     # то же + проект + rig.detect
```

В редакторе ничего делать не надо: перетащили модель без костей — `project.new` сам вызовет авториг.

- Меш → воксели (`bridge/blender/autorig.py`, 128 на длинную сторону; лучи по трём осям и сама поверхность —
  тонкие крылья и плавники не пропадают). Сфера-подставка или пол рядом с персонажем отбрасываются, как в «глазах».
- Скелет (`autorig_core.py`, только numpy): от самой толстой точки тела считается расстояние «по телу», тело режется
  на слои этого расстояния, связная часть слоя — узел. Лапы, хвост, шея, щупальца отходят отдельными частями слоя,
  поэтому развилки находятся без знания, что это за существо. Короткие бугорки (меряются от поверхности, не от оси)
  отбрасываются, ветки режутся на кости равной длины.
- Корень — самая нижняя развилка, где сходятся три длинные ветки: у человека и птицы это таз, у паука — центр тела.
  У тел-линий (рыба, змея, щупальце) корень — в конце тела, и всё тело — одна цепочка `body`.
- Веса — «теплом» Blender; если меш дырявый — по близости к костям. Мелкие отдельные детали (глаза, ботинки,
  голова сборного робота) жёстко на одну кость; длинные вытянутые (нога-цилиндр) гнутся.
- Проверено на 12 моделях с заранее известным типом тела: скелет выбрасывался, строился заново и распознавался
  `rig.detect` — все 12 совпали (человек ×4, четвероногое ×2, паук, насекомое, птица, черепаха, рыба, змея).
  Отладка: `AUTORIG_DEBUG=1` и `python3 bridge/blender/debug_autorig.py out.glb` — проекции вокселей и костей.
- Распознавание безымянных скелетов стало строже: «ноги» по геометрии должны идти вниз (опускание ≥ 0.6 длины),
  иначе это плавники или ласты (`detectFins`); крылья могут расти прямо из таза; широкая пара ласт — крылья.
- Blender запускается со своим каталогом пользователя (`BLENDER_USER_RESOURCES`): фоновые запуски не трогают
  расширения владельца — иначе параллельные запуски стирают друг у друга их пакеты в site-packages.

Пальцы — по флагу `--fingers true`: у кончиков рук форма вокселится мельче (1/48 длины кисти), и если за ладонью
расходятся 4–6 тонких почти параллельных отростков похожей длины, кончик заменяется ладонью с пальцами.
Ступни и макушка не проверяются (там на мелкой сетке «пальцами» выглядят детали обуви и черепа). На синтетической
руке находит, на 12 моделях проверки ложных пальцев нет; у Xbot пальцы сомкнуты — не находит.

Сборные модели (робот из деталей, Xbot), где тепло Blender не справилось: суставы сдвигаются к стыкам деталей,
суставы посреди цельной детали убираются, и каждая деталь целиком на своей кости — бедро не мнётся. Запасные веса
берут только кости, к которым от вершины есть путь внутри тела, и сглаживаются по рёбрам меша.
