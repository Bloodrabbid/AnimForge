# AnimForge

Инструмент анимации под любую игру: рецепты с параметрами + ручной слой правок + клипы, экспорт в glTF, проверка в Godot.
Одно ядро команд (`packages/core`) — его вызывают CLI, MCP и веб-интерфейс.

## Быстрый старт

```sh
pnpm install
P=projects/fish-demo
pnpm af help                                   # все команды с аргументами (JSON)
pnpm af info --project $P                      # кости, цепочки, клипы
pnpm af preset.list --project $P               # пресеты библиотеки
pnpm af recipe.set --clip swim --layer wave --params '{"period":1.6}' --project $P
pnpm af key.set --clip swim --bone spine_5 --axis lateral --t 1.0 --v 25 --project $P
pnpm af sheet --clip swim --view top --out out/swim.png --project $P   # «глаза»: лист кадров через Blender
pnpm af export --out out/fish.glb --project $P                         # glTF для Blender/Godot/любого движка
pnpm af verify --project $P                                            # проверка в Godot без окна
```

## make: от модели до файла одним вызовом

```sh
pnpm af make --project out/baker --file ~/models/baker.glb \
  --clips "ленивая ходьба; удар; дыхание" \
  --style '{"stylization":"cartoon","role":"npc","fps":30}' \
  --godot ~/games/clay/godot/assets/anim --send
```

Одна команда делает всё по порядку:

1. Создаёт проект: импорт модели и авториг, если скелета нет.
2. Собирает клипы из библиотеки. Если анатомических пределов ещё нет, ставит их.
3. Экспортирует glb в `out/<имя>.glb` и кладёт копию в папку игры на Godot.
4. Рендерит видео всех клипов с подписями в `out/<имя>.mp4`.
5. С `--send` присылает видео и glb в Telegram.

**Клипы** перечисляются через `;`:
- `имя=пресет{"period":0.6}` — точный пресет с параметрами;
- просто `пресет`;
- слова: «ленивая ходьба», «ходьба как у голема», «акула плывёт».

Поиск по словам (`searchPresets` в `packages/core/src/plan.ts`) учитывает:
- раздел библиотеки;
- прилагательные (ленивая → спокойная, тяжёлая → голем);
- прямые упоминания;
- тело: двуногому не достанется походка многоногого;
- карточку стиля.

Бег и силовой удар выбираются, только если о них просят. Чего в библиотеке нет, то честно попадает в `missing`. В отчёте `summary` для каждого клипа указаны выбранный пресет и ещё три варианта.

**Карточка стиля** (`style`) и **папка игры** (`godot`) запоминаются в проекте, повторять их не нужно. Поля карточки:
- `stylization`: realistic / cartoon;
- `role`: player / enemy / npc;
- `fps`, `genre`, `refs`, `notes`.

От карточки зависит выбор пресетов: мультяшному персонажу достаются движения Tools Up!, реалистичному — Witcher и TLJ, NPC — пресеты с читаемым телеграфом (заметным замахом перед ударом).

Повторный `make` с тем же именем клипа заменяет клип, так что править можно тем же вызовом: `--clips "walk=toolsup-heavy"`.

**Остановки:**
- в модели нет мешей (файл — только скелет);
- риг сомнительный: цепочек нет или тело не узнано. Тогда `make` рисует модель в `out/make-rig.png` и ждёт вызова с `--force`.

Длина разового клипа берётся из рецепта (`length`). Удар длится до открытия окна ввода, силовой заряд — целиком.

## Веб-интерфейс

```sh
pnpm web                     # http://localhost:5178/?dir=projects/fish-demo  (порт — PORT=…)
pnpm web:shot 't=0.3&paused=1&bone=spine_5' out/web/t0.3.png   # скриншот без окна (headless Chromium по CDP)
AF_URL=https://… pnpm web:shot x out/web/other.png              # снять любую страницу (AF_WAIT_MS, AF_EVAL — JS перед снимком)
```

- **Своя модель**: перетащите FBX, GLB, glTF (одним файлом) или DAE в окно или нажмите «Загрузить модель».
  Сервер (`POST /api/upload` → команда `project.new`) импортирует её через Blender, распознаёт скелет и открывает
  новый проект в `out/uploads/<имя>` (в git не попадает). Без скелета со скином — понятная ошибка, полупроект удаляется.
  Из CLI то же самое: `pnpm af project.new --file ~/Downloads/hero.fbx --project out/uploads/hero`.
- **Библиотека** (слева): все пресеты с поиском, разделами по типу движения и происхождением (Witcher 3, DREDGE, TLJ…).
  На карточке — кривые главной кости за цикл, их считает само ядро. Тип тела берётся из `rig.detect` без записи,
  поэтому четвероногому первыми показываются походки, пауку — ноги; то, на что не хватает цепочек, скрыто.
- **Примерка**: клик по карточке — клип с этим движением сразу играет на вашей модели, на диск ничего не пишется
  (`POST /api/preview`: те же команды на копии проекта). Ползунки во время примерки тоже правят копию.
  «Применить» (Enter) повторяет все шаги командами ядра, Esc — отмена. Походки ставят лапы на пол (`clip.ground`).
- **Слои** одного рецепта и пресета (лапы паука, крылья) собраны в группу: общий параметр правится у всех сразу.
  Слой можно выключить (`layer.set`, вес 0) или убрать (`layer.remove`), клип — удалить (`clip.remove`).
- **Вьюпорт**: ракурсы (F, 1–3), скелет, каркас, пол с тенью, гизмо осей. **Время**: вкладки клипов, кадр назад/вперёд,
  по кругу, скорость ×0.1…×2, линейка кадров с метками событий рецептов. Горячие клавиши — по «?».
- **Веса** (вкладка справа): модель красится тепловой картой выбранной кости (синий 0 → красный 1), кистью —
  добавить, убрать, сгладить; клик с Shift или Cmd по модели выбирает кость под курсором, Cmd+Z — отмена мазка.
  Анимация не останавливается: правишь вес прямо в шаге или в примерке из библиотеки. «Сохранить» пишет веса в glb
  модели (`/api/weights`, первый раз исходник ложится рядом — `<модель>.orig.glb`), «Вернуть исходные» — обратно.
  Правка веса одной кости — `setBoneWeight` в ядре: остальные кости делят остаток пропорционально, сумма 1.
- **Скачать GLB** — все клипы, запечённые в glb (`/api/download`), для Godot, Blender и других движков.

Поза во вьюпорте считается вживую ядром (`poseAt`) на каждом кадре; любое действие в интерфейсе — команда ядра
через `POST /api/command` (тот же `call()`, что у CLI). Если `animforge.json` поменять снаружи (`pnpm af key.set …`),
открытая страница перечитает проект сама (SSE `/api/events` + `fs.watch`).
Параметры адреса: `dir`, `clip`, `t`, `paused=1`, `bone` (кость или цепочка), `skeleton=0`, `left=bones`.

## Устройство

- `packages/core` — модель проекта, рецепты, кривые, вычисление позы, запекание в glTF, реестр команд. Работает и в браузере, и в Node.
- `packages/cli` — адаптеры Node: файлы, Blender, Godot; CLI `af`.
- `apps/web` — веб-интерфейс: Vite + React + three.js, dev-сервер `server.ts` с API поверх адаптеров CLI.
- `bridge/blender` — шаблоны тел (авториг-заготовки), импорт чужих моделей, отрисовка кадров.
- `godot/verify` — проверка экспорта в Godot 4.5.
- `library/presets` — пресеты рецептов; у каждого записано происхождение (из каких замеров взят).
- `research/` — контур «Исследование» (приватный): что извлечено из игр, в библиотеку не попадает.
- `projects/` — проекты анимации (`animforge.json` — текст, удобно править и смотреть в git).

## Твины UI и камеры

Пресеты лежат в `library/tweens/{ui,camera}.json`, у каждого указано происхождение (провенанс). Это 12 пресетов UI и 6 пресетов камеры, сняты с DREDGE. Одни и те же формулы считают ядро (`packages/core/src/tweens.ts`) и аддон Godot (`godot/sandbox/addons/animforge`).

```sh
pnpm af tweens.list --target ui
pnpm af tweens.plot --preset jump_spin --out out/tweens/jump_spin.png   # график свойств во времени
pnpm af tweens.verify      # синхронизирует пресеты в аддон и сверяет Godot с ядром без окна
```

Чтобы подключить в свою игру, скопируй `godot/sandbox/addons/animforge` в проект и включи плагин. Дальше:
`AnimForge.play($Panel, "window_in")`, `AnimForge.play($Camera3D, "shake_explosion")`,
`AnimForge.play(btn, "button_cascade_item", {"delay": 0.1 * i})`.

## Каналы, пол и вторичная динамика

Повороты бывают двух видов. `lateral | vertical | roll` идут по осям цепочки, а `pitch | yaw | bank` — по осям тела
(наклон вперёд вокруг бока, поворот вокруг верха, крен вокруг «вперёд»). Рецепты ходьбы и ударов пишутся в осях тела, поэтому одинаково
работают на любом риге, как бы ни были повёрнуты локальные оси костей. Есть ещё сдвиги `move_up | move_forward | move_side`
(в метрах, по осям тела: up = `project.up`, forward = `project.forward`, по умолчанию +Z) и масштаб `scale_up | scale_forward | scale_side`.
Масштаб попадает на ту ось кости, что ближе к нужному направлению. Всё это экспортируется в glTF и сверяется в Godot (`af verify`).

- `af clip.ground --clip walk --bones foot_l,foot_r --mode floor --ik true` ставит ступни на пол после всех слоёв.
  Режим `contact` прижимает тело к полу, режим `floor` не даёт провалиться, `ik` сгибает колено (двухзвенная IK), а не двигает тело.
- Рецепт `jiggle` — уши, усы, хвосты по движению родителя: маятник с пружиной, у пресетов параметры DynamicBone из Tools Up!.
- Рецепт `waddle-walk` — ходьба вразвалку Tools Up! (подскок таза взят покадрово), `blink` — моргание масштабом,
  `compass-step` — шаг-циркуль Biped.
- `af video --clip walk1 --out out/walk.mp4 --view front_3q` — видео клипа; `sheet --view front|profile|front_3q` — виды для персонажей.
- Шаблоны тел: `fish | snake | tentacle | quadruped | biped | worker`.

## Бой, события и вставки в idle

- `melee-strike`: удар или серия. Фазы: замах, взмах с пиком скорости за `hitLag` до контакта, доводка, возврат, окно на следующий ввод.
  Слои ставятся на роли `arm` (плечо→локоть), `core`, `pelvis`. Пресеты: стили Геральта, телеграфы NPC от собаки до голема, молоток Tools Up!.
- `charge-release`: силовая атака — замах, удержание с пружинящим корнем, выпуск двумя ударами (`witcher-power`).
- События рецептов: `hit`, `whoosh`, `effort`, `trail_on/off`, `window_open/close`.
  Посмотреть их: `af clip.events --clip combo`. При экспорте они пишутся в extras анимации и в `<glb>.events.json`.
  В Godot их подключает `AnimForge.attach_events(player, "res://…events.json", self)`, дальше игра получает вызовы `animforge_event(name, clip)`.
- Вставки в idle по шансу и кулдауну (Witcher, TLJ): `AnimForge.idle_variety($AnimationPlayer, "witcher-geralt")`. Пресеты лежат в `library/idle/`.
- `af tweens.verify` проверяет аддон целиком: твины, события и вставки в idle.
- Шаблоны: детали тела слушаются только своих костей (`bodykit.restrict_weights`), поэтому взмах руки не мнёт туловище и голову.

## Чужие модели: перенос на любой скелет

```sh
pnpm af model.import --file Xbot.fbx --out assets/model.glb --project $P   # FBX, glTF, OBJ, DAE → glb со скином
pnpm af rig.detect --project $P            # цепочки, «вперёд», выравнивание рук
pnpm af clip.add --name walk --duration 1 --project $P
pnpm af recipe.rig --clip walk --recipe waddle-walk --preset toolsup-worker --project $P   # слой на каждую роль
pnpm af clip.ground --clip walk --bones LeftFoot,RightFoot --mode floor --ik true --project $P
```

- `rig.detect` узнаёт кости по именам: Mixamo, Unreal, Unity, Rigify, 3ds Max Biped, числовые префиксы.
  Если имён нет, строит цепочки по геометрии. Направление «вперёд» берёт по меткам L/R, а без них — по носкам.
- Руки, которые в rest отходят от «вниз» больше чем на 30° (T- и A-поза), записываются в `project.align`.
  Перед всеми слоями их опускает вниз с отведением 8°, так махи рецептов начинаются из одной позы у любой модели.
- Масштаб узлов учитывается везде: у FBX корень часто в 0.01 (сантиметры), а сдвиги, IK и пол считаются в метрах мира.
- `model.import` сажает кожу на свои кости. У моделей, вытащенных рипером из сцен-витрин, меш и скелет висят под разными узлами.
  Импорт пробует оба толкования вершин (как рисует Blender и как движок) и берёт то, где вершины ближе к своим костям.
- «Глаза» (`sheet`, `video`) рисуют кожу по спецификации glTF, так же как Godot: позу считает ядро, скиннинг — `packages/cli/src/skin.ts`,
  а Blender только рисует треугольники. Импортёр Blender для этого не годится: у таких моделей он показывает кожу не там, где кости.
  Камера вписывает персонажа во всех позах клипа (`--dist 1`) и смотрит ему в лицо по `project.forward`.
- `af verify` сверяет кости в Godot. Godot заменяет `:` в именах костей на `_` (`mixamorig:Hips`), и проверка это учитывает.
  Если кость не найдена, проверка падает, а не сравнивает с нулём.
- Проверено на Xbot (Mixamo, T-поза), Worker и DeliveryGuy (Tools Up!, A-поза, сцена-витрина) и April (The Longest Journey).

## Четвероногие

```sh
pnpm af rig.detect --project $P     # четвероногое узнаётся по лапам, «вперёд» — к голове
pnpm af recipe.rig --clip walk --recipe quadruped-gait --preset witcher-dog-walk --project $P
pnpm af recipe.add --clip walk --recipe jiggle --chain tail --id tail_jiggle --project $P
pnpm af clip.ground --clip walk --bones <4 лапы из rig.detect: paws> --mode floor --ik true --project $P
```

- `rig.detect` узнаёт четвероногое по геометрии, имена не нужны. Внизу должно быть четыре лапы, корень каждой — у тела.
  Передняя пара — та, что ближе к голове. Цепочки те же, что у двуногих: передние лапы — `arm_l/arm_r`, задние — `leg_l/leg_r`,
  таз и грудь — места крепления лап, а также `spine`, `neck`, `head`, `tail`. В ответе есть `paws` — концы лап для `clip.ground`.
- `quadruped-gait` построен по собаке Witcher (`cr_canine`, у баргеста те же клипы). У каждой лапы четыре кривые суставов за цикл:
  плечо или бедро, локоть или колено, пясть или плюсна, пальцы. Вынос лапы быстрый, опора занимает около 70 % цикла.
  Лапы сдвинуты по фазе, корпус качается, шея считается как «своё минус корпус», таз подскакивает.
- Пресеты: `witcher-dog-walk` (шаг, пары почти диагональные), `witcher-dog-run` (поперечный галоп),
  `trot` (рысь) и `pace` (иноходь). В двух последних фазы взяты из определения аллюра, а кривые — от шага собаки.
- Проверено на лисе Khronos Fox (glTF Sample Assets, CC-BY 4.0) и на шаблоне `quadruped`, у которого теперь есть ступни.

## Ограничения (констрейны): диапазон движения костей

Колено не гнётся вперёд, локоть — назад, шея не крутится на 360°, даже если рецепт, ключ или перенос
с чужого скелета этого хотят. Поворот кости раскладывается на кручение и два изгиба (swing-twist), каждый угол
обрезается по своему диапазону. Оси — те же, что у ключей: у кости цепочки `lateral` / `vertical` / `roll`, у
корпуса и головы `pitch` / `yaw` / `bank`. Углы меряются от выровненной позы покоя (рука, опущенная из T-позы,
стоит в нуле). Пределы применяются до пола и IK и ещё раз после вторичной динамики — экспорт тоже обрезан.

```bash
pnpm af limit.auto --project projects/worker-demo                 # анатомия: колени, локти, шея, голова
pnpm af limit.set --bone leg_l_1 --axis vertical --min -150 --max 0
pnpm af limit.set --chain tail --axis lateral --min -40 --max 40  # каждой кости цепочки
pnpm af limit.fit --chain arm_r --margin 5                        # размах «как в клипах» + запас
pnpm af limit.clear --bone head --axis yaw                        # без аргументов — снять всё
```

`limit.auto` сам находит, в какую сторону гнётся сустав: крутит среднюю кость на 20° и смотрит, куда ушёл конец
(стопа — назад, кисть — вперёд); ось сгиба — `vertical` у висящей ноги и `lateral` у руки в T-позе. Диапазоны
0…150° колена и 0…145° локтя — анатомическая норма человека, ±8° вбок и ±15° кручения — на глаз.

В редакторе — вкладка «Пределы»: у выбранной кости ползунки диапазона по осям, синяя метка — где кость сейчас
в клипе (без ограничения), красная — упёрлась; во вьюпорте упёршиеся кости отмечены красными точками.

## Цели: IK, взгляд и копия поворота

IK — кисть или стопа тянется к точке: взять предмет, опереться о стену, поставить ногу на ступеньку. Сгибаются две
кости над кончиком (плечо и локоть, бедро и колено), плечо и таз остаются на месте; до недостижимой цели рука
вытягивается в её сторону. Взгляд — голова и шея поворачиваются на цель, поворот делится между ними поровну.
Цель — точка, кость (смотреть на свою руку) или точка с ключами по времени (провожать взглядом, тянуться за
движущимся). Считается после слоёв и пола, до вторичной динамики; пределы суставов действуют и на цели —
голова не повернётся на 180°, локоть не вывернется. Экспорт запекает результат.

```bash
pnpm af ik.add --clip walk --chain arm_l --target 0.2,0.9,0.4 --project out/demo       # кисть к точке
pnpm af ik.add --clip walk --chain leg_r --target 0.1,0.3,0.3 --pole 0.1,0.5,2           # колено смотрит вперёд
pnpm af aim.add --clip walk --target -0.6,1.0,0.8 --project out/demo                    # шея + голова на точку
pnpm af aim.add --clip walk --targetBone hand_l --id look_hand                          # смотреть на свою кисть
pnpm af constraint.key --clip walk --id aim --t 1.9 --target 0.7,1.0,0.8                # цель поехала
pnpm af constraint.set --clip walk --id ik_arm_l --weight 0.5                           # полпути от анимации к цели
pnpm af constraint.remove --clip walk --id aim
```

Копия поворота — кость повторяет движение другой: второе ухо за первым, хвост за тазом, левая рука зеркально за
правой. Копируется движение источника от его позы покоя (выравнивание из T-позы не в счёт) и добавляется поверх
своей анимации; множитель −1 — в обратную сторону, 0.5 — вполовину. Пружины вторичной динамики считаются потом и
не копируются.

```bash
pnpm af copy.add --clip walk --chain ear_l --sourceChain ear_r --mirror true   # цепочки — кость к кости
pnpm af copy.add --clip walk --bone tail_0 --source pelvis --weight -0.5       # хвост гасит качание таза
```

У руки-варежки без кисти тянется конец предплечья (продолжение на длину плеча). В редакторе — вкладка «Цели»:
кнопки «IK: рука л / нога п / Взгляд» ставят цель там, где кончик сейчас, цель — шарик на модели (IK бирюзовый,
взгляд сиреневый), выбранную тащат стрелками; у цели с ключами перетаскивание ставит ключ в текущем кадре.
Сила, выключение, сторона сгиба (вперёд, назад, вверх, вниз) — в строке цели.

## Позинг: тянуть модель мышью

Режим «Поза» (кнопка с ладонью на панели вьюпорта или клавиша P): суставы — точки на модели, у костей без
дочерних (кисть-варежка, кончик хвоста, ухо) — точка на их конце, длина конца измеряется по коже. Схватили и тянете —
сгибаются N костей над схваченной (выбор рядом с кнопкой: 2 — рука или нога, 3–4 — с ключицей и корпусом, 8 — весь
хвост). Пределы суставов учитываются прямо при подборе позы: если локоть упёрся, догибается плечо, а не обрезается
поза. Отпустили — поза пишется ключом в текущий кадр (слой «pose»: между ключами повороты интерполируются
плавно, ключ посреди старых сохраняет то, что там было). Таз переносит тело целиком: закрепите ступни
(Alt+клик по суставу — IK-цель в текущей точке) и тяните таз вниз — персонаж присядет, колени согнутся сами.
«Сбросить» — убрать ключ позы в кадре.

```bash
pnpm af pose.reach --clip walk --t 0.5 --bone hand_l --target 0.4,1.3,0.3            # кисть в точку, 2 кости
pnpm af pose.reach --clip walk --t 0.5 --bone tail_7 --target 0,0.6,-0.5 --length 8  # весь хвост
pnpm af pose.reach --clip walk --t 0.5 --bone hips --target 0,0.8,0 --length 0       # таз вниз — присесть
pnpm af ik.add --clip walk --chain arm_l --target 0.6,1.1,0.4 --length 5             # IK-цель с корпусом
pnpm af pose.clear --clip walk --t 0.5
```

Решатель — CCD по цепочке с пределами внутри шага; у шарнира (локоть, колено с пределом) точное начало — сгиб
вокруг его оси, затем поворот основания, локоть остаётся ближе к тому месту, где был в анимации; потом ещё
несколько начал, берётся поза, где кончик ближе к цели.

## Авториг: модель без скелета

```sh
pnpm af model.autorig --file ~/Downloads/statue.obj --project out/uploads/statue   # → assets/model.glb со скином
pnpm af project.new --file ~/Downloads/statue.obj --project out/uploads/statue     # то же + проект + rig.detect
```

В редакторе ничего делать не надо: перетащили модель без костей — `project.new` сам вызовет авториг.

- Меш → воксели (`bridge/blender/autorig.py`, 128 на длинную сторону; лучи по трём осям и сама поверхность —
  тонкие крылья и плавники не пропадают). Сфера-подставка или пол рядом с персонажем отбрасываются, как в «глазах».
- Скелет (`autorig_core.py`, только numpy): от самой толстой точки тела считается расстояние «по телу», тело режется
  на слои этого расстояния, связная часть слоя — узел. Лапы, хвост, шея, щупальца отходят отдельными частями слоя,
  поэтому развилки находятся без знания, что это за существо. Короткие бугорки (меряются от поверхности, не от оси)
  отбрасываются, ветки режутся на кости равной длины.
- Корень — самая нижняя развилка, где сходятся три длинные ветки: у человека и птицы это таз, у паука — центр тела.
  У тел-линий (рыба, змея, щупальце) корень — в конце тела, и всё тело — одна цепочка `body`.
- Веса — «теплом» Blender; если меш дырявый — по близости к костям. Мелкие отдельные детали (глаза, ботинки,
  голова сборного робота) жёстко на одну кость; длинные вытянутые (нога-цилиндр) гнутся.
- Проверено на 12 моделях с заранее известным типом тела: скелет выбрасывался, строился заново и распознавался
  `rig.detect` — все 12 совпали (человек ×4, четвероногое ×2, паук, насекомое, птица, черепаха, рыба, змея).
  Отладка: `AUTORIG_DEBUG=1` и `python3 bridge/blender/debug_autorig.py out.glb` — проекции вокселей и костей.
- Распознавание безымянных скелетов стало строже: «ноги» по геометрии должны идти вниз (опускание ≥ 0.6 длины),
  иначе это плавники или ласты (`detectFins`); крылья могут расти прямо из таза; широкая пара ласт — крылья.
- Blender запускается со своим каталогом пользователя (`BLENDER_USER_RESOURCES`): фоновые запуски не трогают
  расширения владельца — иначе параллельные запуски стирают друг у друга их пакеты в site-packages.

Пальцы — по флагу `--fingers true`: у кончиков рук форма вокселится мельче (1/48 длины кисти), и если за ладонью
расходятся 4–6 тонких почти параллельных отростков похожей длины, кончик заменяется ладонью с пальцами.
Ступни и макушка не проверяются (там на мелкой сетке «пальцами» выглядят детали обуви и черепа). На синтетической
руке находит, на 12 моделях проверки ложных пальцев нет; у Xbot пальцы сомкнуты — не находит.

Сборные модели (робот из деталей, Xbot), где тепло Blender не справилось: суставы сдвигаются к стыкам деталей,
суставы посреди цельной детали убираются, и каждая деталь целиком на своей кости — бедро не мнётся. Запасные веса
берут только кости, к которым от вершины есть путь внутри тела, и сглаживаются по рёбрам меша.
